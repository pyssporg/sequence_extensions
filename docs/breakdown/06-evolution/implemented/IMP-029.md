# Expose per-node policy through the engine API

Implemented 2026-11-12 in the `flow-plan/2` migration.

- **Question:** Can per-node policy become a supported engine input instead of private attribute mutation?
- **Evidence:** the GUI mutated `NodeFunction.retries`, `retry_delay_seconds`, and `timeout`, which upstream did not support (`INFO-031`).
- **Change:** `RunOptions.node_policies` is public; `execute_plan` reads policies from the document; precedence puts plan policy above an explicit `@node` keyword.
- **Risk:** none carried into the GUI; the plan document is now the only policy import path.
- **Acceptance:** a policy edit takes effect through the public plan path with no private writes; engine precedence tests and GUI execute tests cover it.
